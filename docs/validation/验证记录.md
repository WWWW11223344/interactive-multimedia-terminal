## 文档和交付复查方式

`python tools/build_docs.py` 将实际测试 BMP 转为带桌面模拟标识的 PNG，生成架构图及 Word 项目书。Word 已核查 ZIP 结构、表格与插图，学生信息留空；设计方案另行生成 `触控休闲娱乐终端项目设计方案.docx/.pdf`，共 29 页、12 张表、13 张插图，目录为 Word 域，页码与正文一致（逐页渲染核对，无空白页、无断表）。未将 Word 在不同 Office 版本中的分页效果作为已验证结果。

`python tools/package.py` 会重新构建、测试并检查交付文件，然后生成源码、Windows 预览、GEC6818 运行三个 ZIP；包内提供文件 SHA256，包外提供整体 SHA256。源码包排除工具链、构建缓存和个人画作，并附本地 Git 历史 bundle（存在本地 Git 时）。Git 作者是 Codex 工具记录，不代填学生姓名，不向外部仓库推送。

打包末尾执行 `python tools/verify_packages.py --preview --rebuild`，核对整包 SHA256、ZIP CRC、包内每个文件的 SHA256、相对路径和 Linux 执行位；在临时目录解压源码并独立配置/编译/运行 CTest，恢复 Git bundle 并比对全部跟踪文件，然后实际运行解压后的 Windows 程序检查绘画与保存。结果写入 `dist/delivery-validation.txt`，该回执置于 ZIP 外，避免把核验中变化的日志打入已完成的包。源码包仍包含本目录的构建、回归、输入保存等原始记录。

使用 `--record-snapshot` 打包时，在构建测试和文档生成之后、创建 ZIP 之前记录本地 Git 版本；提交范围仅为交付源码、文档和资源，不包含构建目录及个人画作。全局 Git 配置不变。

首次 Git bundle 恢复核验发现 Windows 全局 autocrlf 会改变检出文件的换行；已加入 `.gitattributes` 保持实际文件字节，确保 Linux 启动脚本仍为 LF，并重新核对恢复后的全部跟踪文件。未批量转换原源码编码或换行。

## 触摸"上半屏点不动"的处置

现象：登录页第一行 1/2/3 键无反应，4~9 与 0 正常。三行键的矩形只差 68 像素，不存在"半个屏幕"的分界，所以问题不在版式而在坐标映射——驱动声明的 ABS 范围与它实际上报的范围不一致时，就会有一段屏幕被映射到没人点到的位置。

处理分三层，都不依赖"再猜一个偏移量"：

1. 设备层把原始值交给上层。登录页左下角显示 `down / up / raw`，串口每点一次打印 `tap down= mid= up= raw= page=`。原始值在整块区域几乎不变，说明这一段报不出位置；原始值随位置连续变化而映射结果偏掉，说明范围声明错。
2. 五点标定按实测范围重新映射（见 部署与验收）。拟合、外推与偏差判定都在 touch_cal.c 里，可以脱离设备在宿主机上验证。
3. 键盘块改为整块铺满：落在 8 像素缝里、或比键帽高出一点的点击，吸附到最近的键，不再有"差几像素就没反应"的死角。

标定本身也有边界：若面板某一段**根本报不出位置**，任何映射都救不回那一段，只能改版式绕开。因此标定页把失败原因和五组原始值一起显示，而不是悄悄存下一份错的标定。
