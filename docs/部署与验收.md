# 部署与验收

## 板端准备

目标为 GEC6818、32 位 ARM Linux 用户环境、800×480 触摸屏。程序不带内核或驱动，不烧录系统；使用板卡已有 framebuffer 和 evdev。显示支持 packed pixels / true color 的 16 或 32 bpp，启动时检查尺寸、色域、行跨度和内存范围。

1. 解压 `GEC6818-运行包.zip`，将整个目录传到开发板 `/mnt/terminal` 等可写位置，保留 `bin`、`res`、`data`、`run.sh` 的相对关系。
2. 在板上执行 `uname -m`，检查用户系统与 ARM 程序匹配；执行 `cat /proc/bus/input/devices` 定位触摸屏对应的 `eventN`。
3. 退出占用 LCD/触屏的旧演示程序。用板卡系统原有管理方式停止，不使用宽泛的 killall 命令。
4. 执行以下命令，首次运行保留终端输出。

```sh
cd /mnt/terminal
chmod +x bin/terminal run.sh
./run.sh --fb /dev/fb0 --touch /dev/input/event0
```

可以 `./bin/terminal --root /mnt/terminal --touch /dev/input/eventN` 指定根目录；`--data DIR` 可指定已存在父目录下的保存目录。程序不会递归创建未知父目录。所有命令中的 eventN 须替换为实际节点。

## 触摸校准与异常

默认读取驱动报告的 ABS_X/ABS_Y 范围；没有普通坐标轴时尝试 ABS_MT_POSITION_X/Y。启动日志显示分辨率、bpp、stride 与轴范围。如果横纵颠倒，加入 `--swap-xy`；镜像时使用 `--invert-x` 或 `--invert-y`，可组合。

```sh
./run.sh --touch /dev/input/eventN --swap-xy --invert-x
```

### 九点标定（按需，默认不运行）

默认用驱动声明的 ABS 范围启动。这个声明对**跨度**是准的（手指从上沿划到下沿，rawY 覆盖 86..580，与屏幕高度成 1.25 = 600/480），但面板的响应是**弯**的：屏幕 y = 70 / 250 / 430 处分别报 raw 86 / 330 / 518，上段斜率 1.36、下段 1.04。一条直线穿过两端时，屏幕中部会偏 23 像素——正好半行键，这就是"按 1 落成 4"的由来。

所以标定只解决"形状"，不再猜范围：九个十字按 3×3 铺开（x 60/400/740，y 70/250/430），每轴得到三个锚点，映射改成**两段直线**，在中间锚点处接上，不产生台阶；屏幕边缘按各自那一段的斜率外推。加 `--calibrate` 触发，点完九下即可。

每点一下打印 `calibration point N = raw x,y`，结束时打印：

```
calibration applied: swap=0 X=a/b/c Y=d/e/f edges X=.. .. Y=.. .. worst=N
```

`worst` 是九次采样映射回去的最大偏差，超过 40 像素判定失败并列在屏上。`data/touch.cal` 存的是这七个数字（swap + 三个 x 锚点 + 三个 y 锚点），旧格式会被自动忽略。启动时会与声明范围比对：跨度相差超过 1/7 判定为坏记录并忽略，但**偏移放宽到 1/4**——整块位移正是标定要测的东西。

删除 `data/touch.cal` 即回到声明范围。

### 手工排查

先测四角和中心，不要仅用一个按钮判断校准。当前只取主触点。若驱动使用其他非标准触摸协议，应记录设备描述与原始事件后再适配。SYN_DROPPED 的取消逻辑已实现；真实设备丢包、多指和拔插行为尚待实机测试。

登录页左下角实时显示 `down x,y up x,y raw x,y`：按下点、抬起点和**映射前的原始值**。三者一对就能分开三种情况——按下与抬起差得远（手势被当成滑动）、映射后落在别处（范围声明错，跑一次 `--calibrate`）、原始值在整块区域几乎不变（这一段面板报不出位置，只能靠版式避开）。

登录页还会把**最后一次点击的落点画成红色十字**。按下 1 却看见十字落在 4 上，就是"映射把整行推低了一行"，不必再靠读数换算。

### 触摸自检：`--probe` 与 `--trace-abs`

映射本身出错和面板报不出位置，映射后的坐标看起来一模一样，靠截图分辨不出来。两个开关都只读，不改映射、不写标定文件，专门用来把这两件事分开：

```sh
./run.sh --probe        # 全屏自检画面
./run.sh --trace-abs    # 串口逐条打印原始事件
```

`--probe` 把屏幕分成六条横带并标出 y 起点，读数面板放在**下方**，把可疑的上半屏整段让出来。手指从上沿慢慢滑到下沿，看两件事：青色横线是否一路跟着下移；`rawY 见过` 的最小值是多少。松手时串口打印一行，数值可直接贴出来：

```
probe: map=486,352 raw=612,430 seen X=595..612 Y=326..430
```

### 触摸自检：`--sweep` 逐带计数

`--probe` 只能显示有样本的地方。一条一个样本都收不到的横带，在它上面什么都不会动，看不出是「没上报」还是「上报了同一个位置」。`--sweep` 把屏幕切成 24 条 20 像素高的横带，逐带统计样本数与 `rawY` 范围，空带就是那根不存在的柱子：

```sh
./run.sh --sweep        # 竖扫自检；不读 data/touch.cal
```

手指按在上沿，慢慢拖到下沿，再反着拖回上沿，然后松手。判读看柱子的颜色：

| 屏上 | 含义 |
| --- | --- |
| 该带有绿柱 | 这一段正常，`rawY` 随手指变化 |
| 该带有红柱 | 这一段在报事件，但 `rawY` 只有一个值：位置信息丢了 |
| 该带没有柱 | 这一段一个样本都没有，触点整段不上报 |

松手时串口打印三行：`sweep empty:` 列出空带的 y 范围，`sweep map:` 是 24 个计数，`sweep band ... stuck=N at y=M` 是连续多少次 `rawY` 完全没变、从哪个 y 开始。`--sweep` 故意不读标定文件：诊断不能拿一份本身可疑的记录当尺子。

### 登录页：演示账号 `678678`

这块屏上实测失效的是键盘**最上面一行 `1 2 3`**；`4 5 6`、`7 8 9`、`删除 0 确认` 都能正常按。所以登录页可以用，只是账号不能含 `1 2 3`。

演示账号因此定为 `678678` / `678678`（见 `LoginSystem.c` 的 `DEMO_USER` / `DEMO_PASS`），登录页左下角直接把这行字印在屏幕上。`login_init` 采用**追加**而不是覆盖：`data/accounts.txt` 会在重装后保留，用覆盖写法的话旧版留下的 `123456` 会让新账号永远写不进去。已有文件里的账号（含用户自己注册的）都不受影响。

按键顺序：

1. 按 `6 7 8 6 7 8`，满 6 位自动跳到密码格；
2. 再按 `6 7 8 6 7 8`；
3. 按键盘**右下角的「确认」**。

不要点左列那个大的「登 录」按钮：它在 y 250~310，整块落在按不到的范围里。右下角的「确认」在 y 394~454，可以按。状态栏的 `x / 6 位` 计数可以确认每次按键是否真的进去了。

备用开关：

```sh
./run.sh --skip-login    # 跳过登录页，直接进主页
```

`--skip-login` 只在启动时把初始页面改成主页，登录代码与账号文件都不动，换回正常面板后不带这个参数即可。

按实测失效范围估算的可操作情况：

| 页面 | 可操作 | 不可操作 |
| --- | --- | --- |
| 登录 | `4 5 6` / `7 8 9` / `删除 0 确认`，右下角「确认」 | 最上面一行 `1 2 3`、左列「登 录」「注 册」 |
| 主页 | 三张卡片的下半段、退出按钮 | 卡片上部那一段 |
| 电子相册 | 缩略图第一行上半、大图任意位置、底部三个按钮 | 缩略图行的中部 |
| 创意画板 | 返回 / 清屏 / 保存、色板、粗细、画布上段与下段 | 画布中间那一横条 |
| 小游戏 | 四行入口全部（重排后位于 y 260~478） | 上方说明区（只显示，本就不可点） |
| 2048 | 在棋盘下半滑动（滑动手势，没有方向键） | 棋盘上半 |
| 井字棋 / 五子棋 / 象棋 | 在棋盘下半落子 | 棋盘上半的落点 |

失效带的下边界在 y 257 附近（键盘 `4 5 6` 从 258 起可用，游戏菜单旧布局的上排 104..256 点不动，因此重排到了 260 以下）。上边界没有单独测量，只知道画板工具栏在 y 16~76 且确实可用，所以这条带位于画面中部一段，不是整片上半屏。

现场说明硬件问题时，直接用 `./run.sh --sweep` 把失效带指出来，比口头解释有力。

画板上出现完全水平的直线、笔画末端从斜线突然转成横线，就是 `rawY` 定住的直接证据——手指还在往上走，坐标不动了，笔画只能横着走。

`--trace-abs` 启动时列出驱动公布的每一条 ABS 轴及其量程与当前值，之后每条原始事件一行。gslx680 常同时上报 `ABS_X/ABS_Y` 与 `ABS_MT_POSITION_X/Y`，两条通道量程可能不同，程序默认只用前者；这份列表用来判断第二条能否接手。

判读方式：

| 现象 | 含义 | 下一步 |
| --- | --- | --- |
| 手指上移，青线上移，但 `rawY` 最小值卡在某个数不再变小 | 这一段面板报不出位置 | 软件救不回来，改版式避开，或确认能否换通道 |
| 竖扫里某一段是红柱或干脆没有柱 | 面板在那一段报不出位置（见 `--sweep`） | 记下该带的 y 范围与 `rawY`；软件补不出位置，只能改版式避让或换通道 |
| `rawY` 全程线性变化，只是青线位置偏 | 范围/斜率不对 | 删除 `data/touch.cal` 重跑标定 |
| 列表里出现 `ABS_MT_POSITION_Y` 且量程不同 | 可能还有一条通道 | 记录两者数值后决定切换 |

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| Permission denied | 核对执行位、挂载 noexec、设备访问权限；使用板卡已有授权账户 |
| Exec format error | 核对架构与系统，不把 Windows 的 terminal.exe 复制到板上运行 |
| Resource initialization failed | 从包根目录启动，检查 res/simfang.ttf 和 res/game/0..11.bmp |
| Device initialization / Unsupported framebuffer | 保存启动日志，核对 framebuffer 节点、800×480、16/32 位 true color |
| 触摸无效或偏移 | 先看登录页底部的 `raw` 读数；范围声明错就跑五点标定（删 `data/touch.cal`），仍不对再跑 `./run.sh --probe`（见上一节：区分"映射算错"与"这一段面板报不出位置"），必要时用 `--trace-abs` 看驱动公布的轴 |
| 保存失败 | 检查 data/drawings 可写及剩余空间，程序会在画板下方提示失败 |
| 时钟不正确 | 程序显示系统本地时间，无联网校时；在系统层设置时间和时区 |
| 新增图片不显示 | 仅支持未压缩 24/32 位 BMP；退出相册后重进刷新；最多 128 张 |

## 实机录像顺序

录制时让开发板和触屏进入镜头，说明硬件与程序版本。展示首页时间，进入相册翻页和放大，再进入小游戏列表依次演示 2048 合并计分、五子棋与电脑对下一手、井字棋和象棋走一步，最后画一幅图保存、返回相册查看该作品。镜头覆盖触摸手势和屏幕响应。

框架讲解使用 `程序框架.md` 和 `演示讲稿.md` 的顺序，打开实际源码和构建文件解释。视频由学生自行录制；在桌面预览录制时注明桌面模拟，在板上录制时保留开发板和触屏画面。
