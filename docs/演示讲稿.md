# 演示顺序与讲解提纲

视频由学生自行录制，本工程不附生成的视频。以下顺序可合成一段，也可分别录制成果演示和框架讲解。个人姓名、班级请按实际填写。

## 成果演示（建议 3～4 分钟）

1. 开场：题目是《基于嵌入式 Linux 的交互式多媒体终端设计与实现》，目标硬件是 GEC6818 和 800×480 触摸屏，功能是时钟主页、电子相册、四款小游戏（2048／五子棋／井字棋／中国象棋）和创意画板。若在电脑录制，明确说“这是桌面模拟”。
2. 主页：说明时间来自系统本地时间，点击三个入口可进入对应功能，每页都有返回按钮。若板上是第一次运行，先演示五点标定：屏幕依次出现五个十字，各点一下后显示实测的 X/Y 原始范围与最大偏差，然后才进入登录页——这一页解决的是"某几个键怎么点都没反应"，讲清"按实测范围映射，而不是相信驱动声明的范围"。
3. 相册：展示内置图片、翻页、点击放大和上一张/下一张，说明只支持 BMP 图片。
4. 小游戏：主页第二张卡片进入小游戏列表，四张卡片一次说明。先点 2048，用方向按钮或滑动操作，展示相同数字合并、得分变化，最后点重新开始；再返回列表进五子棋，落两手让电脑应手；井字棋点两格说明电脑不会输；中国象棋选中一枚兵或马，展示绿点可走、红圈可吃。
5. 画板：依次选择两种颜色、两档笔触，画简单图形；用白色擦除一段；点击保存，展示保存成功提示。清屏会清除当前画布，不会删除已保存文件。
6. 联动：返回主页，再进相册，点击刚保存的画作并放大。这一步展示两个功能通过 BMP 文件衔接。
7. 收尾：返回主页并正常退出。板上已验证的内容按实际说明，未验证的项目保留为后续验收，不报未经测量的帧率或延迟。

## 程序框架讲解（建议 3～5 分钟）

1. 展示目录：src 放 C 实现，inc 放头文件，res 放图片和字体，lib 放库说明；Makefile 和 CMake 负责构建，tests 是规则与联动验证，docs 是项目资料。
2. 打开 `inc/terminal.h`：App 统一持有画面、画布、四副棋盘和相册。Page 有登录、注册、主页、相册、照片、小游戏列表、2048、五子棋、井字棋、象棋、画板十一个状态，返回键按层级回退。
3. 打开 `src/main.c`：先解析参数，再初始化 App 和平台；主循环执行 tick、按需 render、poll 输入和 event 分发，退出时先关平台再释放资源。
4. 打开 `src/System.c`：单线程统一分发事件。按钮需要按下和松开均在区域内，CANCEL 取消手势，防止拖出后误触。
5. 打开 `src/system/platform.c`：Linux 使用 framebuffer 和 evdev；Windows 分支只是同一套功能的预览。设备节点、XY 交换和轴反转由参数控制。
6. 打开 `src/system/touch_cal.c` 和 `calibrate.c`：驱动声明的轴范围和它真正上报的范围可能不一致，于是屏幕有一段被映射到没人点到的坐标；五点标定把实测范围拟合出来，边缘靠外推。数学部分不引用屏幕和设备，`tests/test_touch_cal.c` 用假面板在宿主机上验证。
7. 打开 `src/WhiteboardSystem.c` 和 `src/AlbumSystem.c`：画板保存 BMP 到 data/drawings；进入相册重新扫描该目录，避免两个页面直接修改对方的状态。
8. 打开 `src/game.c`：棋盘存数字指数；先压缩再合并，单次移动每个数字只能合并一次；有变化才新增数字。界面和按钮放在 GameSystem.c。
9. 打开 `src/boardgames.c`：三个棋种共用一套规则接口，页面只做坐标换算和绘制；`tests/test_boards.c` 只链接这一个文件，就能跑马腿、象眼、炮架和将帅照面。
10. 展示 CTest 输出与部署验收表：主机自动测试已覆盖规则、BMP、触摸标定和页面联动；真实触摸、显示格式及长时间运行还要在板上逐项确认。
